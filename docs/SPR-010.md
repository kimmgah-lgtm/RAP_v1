# SPR-010 — Research Output & Reproducible Report Engine

Status: **Complete; Turn B Final Gate PASS — local/mock development only**.

## Scope

SPR-010 converts authoritative, verified RAP state into deterministic structured artifacts. It adds an Output Specification, immutable logical Output Dataset, versioned Artifact identity, Reproducibility Manifest, deterministic Export Package abstraction, stale detection, and SQLite persistence through the existing RAP operation ledger.

The engine does not replace Zotero, Google Drive, Common Study Review, project Meta Coding, Evidence Graph, or SPR-009 synthesis. Each output row retains its upstream record identity, and scientific results are copied from verified SPR-009 results rather than recalculated in the report layer.

Publication-bias points provide funnel-ready factual data. Figure rendering is not implemented; figure data remains independent of a future renderer.

## Reproducibility contract

Scientifically meaningful specification fields are explicit and contribute to `ConfigHash`. Dataset rows are canonicalized and sorted before hashing. Artifacts retain `ArtifactId`, `ArtifactRecordId`, `ArtifactVersion`, specification and dataset IDs, source/config/content hashes, generator version, and upstream Analysis, Effect Size, Evidence, and Paper lineage.

Equivalent inputs produce equivalent dataset, content, manifest, and package hashes. A meaningful output-configuration change produces a distinct artifact version. SQLite persistence keys artifact history by artifact identity plus version.

An output operation uses the standard `OperationID + PayloadHash` contract. SQLite commits output state, audit data, and the completed operation in one transaction. Therefore persistent multi-step restart recovery is **N/A**: no independently resumable external file-generation phase exists in Turn A; an interrupted SQLite transaction does not finalize partial state.

## Researcher ownership boundary

The dataset builder rejects `Introduction`, `Discussion`, `Conclusion`, `ReviewerInterpretation`, `ReviewerMemo`, and `CriticalAppraisal`, including blank values. AI-assisted or pending records cannot enter a confirmed output. The constrained factual statement template reports only verified counts, pooled estimates, and confidence intervals. It does not add magnitude, causal, publication-bias, significance, implication, recommendation, or conclusion language.

## Export and file safety

Export packages contain identities, generator/schema versions, manifest references, validation state, and content hashes, not canonical PDFs or source databases. Credential-like files, API tokens, canonical PDFs, and private notes are explicitly rejected or excluded by default. Logical destinations reject traversal and absolute paths. Validation recomputes artifact, manifest, and package hashes from actual content. No physical export files or external transfers are performed.

## Readiness and missingness

Conflicting inputs are retained as `CONFLICTING_INPUT` and cannot produce a READY artifact. Missing screening history returns `MISSING_REQUIRED_DATA` with `SCREENING_HISTORY`; no PRISMA count or compliance claim is fabricated. Missing study values remain explicit (`NOT_REPORTED`).

## Known limitations

- No rendered charts or diagrams; only deterministic figure-ready data is implemented.
- No physical archive/file writer; Export Package is a validated, machine-readable local abstraction.
- Screening-flow output depends on authoritative screening history and is unavailable when that history is absent.
- No claim of PRISMA compliance is generated.
- Real external-system validation remains `TEST_DEFERRED`.
