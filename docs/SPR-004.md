# SPR-004 — Google Drive Connector & Verification Engine

## Canonical ownership

- Bibliographic metadata: Zotero
- PDF binary: Google Drive
- Library_ID: Research Library Master
- Review: Notion
- Research knowledge: Obsidian

Zotero Storage is never used. Zotero retains linked attachment references only.

## Delivered

- GET-only Google Drive connector
- Recursive folder and PDF discovery
- Rebuildable in-memory Drive index
- SHA-256 calculation and comparison
- Linked attachment verification
- Missing, broken, wrong-file, duplicate-link, duplicate-PDF, hash-failure, and orphan reporting
- Append-only verification audit
- Integrity health-dashboard components

## Safety

The connector has no upload, update, move, rename, permission, or delete method. The integrity engine is report-only. Tests use an injected mock Drive transport and immutable PDF byte arrays; no external Drive account or research PDF is changed.

ADR-0010 is enforced: filenames are human-readable only and never serve as unique identifiers. Linked verification requires Drive File ID; filename is used only as a reporting signal. Library_ID is never derived from or written into a filename.

## Configuration

Set `googleDrive.folderId` to the approved canonical PDF root and put the access token in the environment variable named by `accessTokenEnvironmentVariable`. Tokens are never stored in configuration or audit logs.

## Verification

Run `pwsh -NoProfile -File ./tools/Invoke-Tests.ps1`. Connector, scan, SHA-256, integrity, broken-link, duplicate, API-unavailable, no-modification, and acceptance tests must pass.
