# SPR-011 — Research Workflow & Exception Management Engine

Status: **Turn A complete; Turn B Final Gate failed; Turn C remediation verified; Turn D Final Gate failed; Turn E P1 remediation verified on native Windows — Final Gate re-verification (Turn F) not performed**.

## Purpose and boundary

SPR-011 detects inconsistencies across authoritative RAP references and manages their exception lifecycle. It does not replace Zotero, Google Drive, Notion, Meta Coding, Evidence Graph, Synthesis, or Output state. The registry stores exception identity, evidence, plans, reconciliation results, verification, and audit data—not duplicate canonical research records.

## Implemented flow

`authoritative fixture snapshot → detector → exception registry → resolution planner → bounded reconciliation → verification → atomic persistence/audit`

- `Get-RapExceptionTaxonomy`: returns the 13 explicit exception classes and safe defaults.
- `Find-RapWorkflowExceptions`: performs deterministic integrity checks without mutation.
- `New-RapExceptionResolutionPlan`: emits one of four resolution states and rejects unsafe AUTO_SAFE escalation.
- `Invoke-RapExceptionReconciliation`: changes only local derived-version state for `STALE`; review/blocked/ignored cases preserve state.
- `Test-RapExceptionResolution`: verifies Library_ID, HUMAN_OWNED, researcher-confirmed data, prohibited actions, and detector outcome.
- `Invoke-RapWorkflowExceptionOperation`: provides registry deduplication, OperationID/PayloadHash replay safety, orchestration, and audit.
- SQLite persistence commits registry state, operation completion, and audit in one transaction through the existing RAP queue database.

## Turn-C composite safety policy

Turn B reproduced a policy defect in which `STALE` reconciled independently while `LIBRARY_ID_LINKAGE_BROKEN` was active for the same entity. Turn C adds `Get-RapCompositeResolutionPolicy` and policy version `SPR-011-TURN-C-1`.

- Resolution is computed once from the complete active exception set, not independently from the most permissive exception.
- Conservative precedence is `BLOCKED > HUMAN_REVIEW_REQUIRED > AUTO_SAFE`.
- AUTO_SAFE uses explicit identity, canonical resolution, ownership, non-destructive, idempotency, verification, lineage, and higher-priority-exception predicates.
- Missing or malformed safety evidence fails closed.
- Identity blockers, unresolved orphan/manual identity, human-owned conflicts, researcher-confirmed conflicts, broken lineage, and unknown conditions prevent AUTO_SAFE.
- Policy version, hash, decision, and reason are persisted in the plan/result/audit path.
- The same exception set produces the same policy hash regardless of ordering, duplication, persistence reload, or process restart.

## Resolution states

- `AUTO_SAFE`: limited in Turn A to refreshing local derived-version state for `STALE`.
- `HUMAN_REVIEW_REQUIRED`: preserves state and requests a human decision.
- `BLOCKED`: preserves state and prevents unsafe continuation.
- `IGNORE_WITH_JUSTIFICATION`: requires a non-empty recorded justification and does not mutate authoritative state.

## Safety contract

Plans cannot contain delete, merge, arbitrary canonical selection, HUMAN_OWNED overwrite, researcher-confirmed overwrite, or production-write actions. Verification rejects changes to `Library_ID`, HUMAN_OWNED content, or researcher-confirmed coding. Audit records explicit zero counts for delete, merge, canonical selection, and protected-field writes.

Production write is disabled. Turn A uses only deterministic fixture/mock snapshots, makes no real Zotero/Drive/Notion changes, and performs no external production test.

### Taxonomy (RISK-SPR011-002)

- 14 classes: added `AUTOMATION_FAILURE` (BLOCKED, component `AUTOMATION`), detected from `Snapshot.AutomationRuns` when ExitCode ≠ 0, status is FAILED/TIMEOUT/ERROR/CANCELLED, or error evidence exists. Exit 0 with error evidence is recorded as `Masked=true` (cf. v6.1 rule B-3).
- `ConvertTo-RapExceptionClass` accepts only an exact ordinal taxonomy match; null, empty, padded, differently-cased, or unknown classes become `UNKNOWN_EXCEPTION`. `ConvertTo-RapNormalizedException` keeps the original class as evidence.
- The composite policy no longer trusts exception objects: an unsupported class or a `DefaultResolution` that differs from the taxonomy fails policy evaluation → BLOCKED.

### Downstream semantics (RISK-SPR011-003; E05/E06/E10/E11)

- `Snapshot.Dependents` is the normalized projection of Evidence-Graph lineage (ArtifactId, ArtifactType, Requires PDF/SOURCE_VERSION, Upstream, recorded Status, basis hash/version). No competing lineage store is created.
- `Get-RapDownstreamImpact` derives effective status from evidence, never from a recorded CURRENT: BLOCKED > REVALIDATION_REQUIRED > STALE > CURRENT, propagated transitively; missing upstream references and cycles block.
- `Test-RapDependentOperationPermitted` is the executable gate: only CURRENT is permitted; unknown artifacts are refused.
- E05: PDF evidence has `Condition=MISSING`, `DownstreamBlockModeled=true`, and the BLOCKED dependents; E06: `Condition=HASH_CHANGED` with all four dependents REVALIDATION_REQUIRED, recorded as `DEPENDENT_STATUS_TRANSITION` events, no recomputation; E10: per-field AI value, model id, model version, run id, provenance completeness, researcher value/hash and confirmation provenance; reconciliation returns `RetainedAlternatives` (`RETAINED_NOT_APPLIED`, `Applied=false`) persisted in the registry; E11: STALE evidence lists dependents; the AUTO_SAFE DerivedVersion refresh does not make dependents CURRENT; only new basis evidence does.
- Verification additionally fails on rewritten lineage (`DEPENDENT_LINEAGE_REWRITTEN`) or missing AI retention (`AI_ALTERNATIVE_NOT_RETAINED`).

### Lifecycle audit (RISK-SPR011-004)

- `WorkflowLifecycleEvents` is append-only and SHA-256 hash-chained (`RowHash = SHA256(PrevHash|event JSON)`, `PrevHash` UNIQUE); `WorkflowChainHead` anchors count and last hash; each `OPERATION_COMPLETED` event binds its audit row by `AuditJsonHash`.
- Events: DETECTED → PLANNED → RECONCILIATION_APPLIED/STATE_PRESERVED → VERIFIED/VERIFICATION_FAILED → FINAL_RESOLUTION (auto) or AWAITING_HUMAN_REVIEW; HUMAN_REVIEW_DECISION → FINAL_RESOLUTION (researcher); DEPENDENT_STATUS_TRANSITION; OPERATION_COMPLETED; OPERATION_FAILED. Each carries actor, actor type, from/to state, failure reason, timestamp, policy version.
- Audit rows (`AuditSchema=SPR-011-TURN-E`) persist actor, prior state and hash, after-state hashes, final statuses, downstream transitions, failure reason.
- `Submit-RapHumanReviewDecision`: researcher-only (`ActorType=RESEARCHER`, automation prefix rejected in any case), authorized list, rationale required, non-destructive decision vocabulary (`KEEP_BLOCKED`, `KEEP_RESEARCHER_VALUE`, `REQUIRE_REVALIDATION`, `ACCEPT_WITH_JUSTIFICATION`), idempotent by DecisionId. A later operation that observes the same problem reopens the case.
- `Get-RapExceptionLifecycle` reconstructs a case from the store alone; `Test-RapWorkflowAuditChain` verifies the chain.
