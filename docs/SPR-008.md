## Model and boundaries

The Evidence Graph stores typed references and relationships. It does not copy or redefine authoritative Zotero bibliographic metadata, Drive PDFs, Notion Common Reviews, Project Sheet judgments, or Meta Coding records. Paper nodes use `Library_ID`; project-specific nodes use `Library_ID + Project_ID`.

Supported node semantics include Paper, Project, Project-Paper, Common Review, Evidence, AI Extraction, Meta Coding, Outcome, Comparison, Effect Size, Measurement, Time Point, Statistical Input, Derived Value, and Researcher-Confirmed Record. Supported relationship semantics include review/evidence ownership, project inclusion, paper references, Meta Coding containment, effect/statistical-input support, derivation lineage, extraction provenance, and explicit confirmation.

Evidence IDs and edge IDs are deterministic SHA-256-derived identities. Evidence nodes retain source, location, snippet, method, confidence, generation, prompt, schema, value, and status metadata. `SUPPORTED`, `INFERRED`, `NOT_REPORTED`, `UNCERTAIN`, and `CONFLICTING_EVIDENCE` remain unchanged by graph linkage.

## Persistence and safety

Local SQLite stores graph nodes, edges, a rebuildable snapshot, audit events, and operation checkpoints. The existing RAP `Operations` ledger enforces OperationID/PayloadHash replay and conflict behavior. Independent Process A/Process B recovery resumes a `PREPARED` graph operation idempotently.

Only DryRun and Fixture modes are exposed. No external graph database, AI provider, Zotero write, Drive migration, or Notion write is used.
