# SPR-003 — Transactional Write Layer

## Safety boundary

The Write Layer is disabled by default. A context can be created only for a numeric Zotero group ID whose remotely reported name contains `Sandbox`. Production libraries and user libraries are rejected. Tests use an in-memory mock transport and never call Zotero.

## Pipeline

Every command follows validation, dry-run decision, snapshot, write, post-write read, verification, commit, audit, or compensating rollback. Verification failure creates an error-queue record marked for human review and emits `RollbackExecuted`.

## Commands

- `WriteLibraryIdCommand`: writes `Library_ID: LIB:L000001` in Extra and returns `ALREADY_EXISTS` without writing when present.
- `WriteExtraCommand`: replaces Extra.
- `WriteTagCommand`: adds only `rap:` system tags.
- `AddCollectionCommand`: adds one collection membership.
- `UpdateMetadataCommand`: updates only title, DOI, ISBN, date, or publicationTitle.
- `CreateLinkedAttachmentCommand`: registers an absolute linked-file path.

## Approved rollback exception

Rollback may remove a tag, collection membership, or linked attachment only when the same `OperationID` created it in the active Sandbox transaction. Existing data is restored from the snapshot and is never deleted. Attachment rollback requires both the returned created key and matching operation ownership metadata.

## Configuration and execution

Set `writeLayer.enabled` only after configuring and independently verifying the Sandbox group ID. Keep the API key in the configured environment variable. `Run-Agent.ps1 -DryRun` enables agent dry-run mode; operation APIs also require `-DryRun` to suppress their write.

## Tests

Transaction, rollback, verification, queue, audit, idempotency, dry-run, invalid-item, linked-attachment, and production-library rejection tests run against a mock Sandbox transport.
