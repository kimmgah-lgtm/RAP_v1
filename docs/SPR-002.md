# SPR-002 — Zotero Read-Only Connector

## Objective

Provide one normalized, read-only Zotero boundary backed by SQLite or the Zotero Web API without exposing source schemas to the platform.

## Delivered

- `ZoteroConnector.psm1` facade (`IZoteroConnector` boundary)
- SQLite reader using `SQLITE_OPEN_READONLY`
- GET-only Web API reader with remote HTTPS enforcement
- Normalized item, attachment, and collection models
- Collections, items, metadata, creators, tags, Extra, notes, child items, attachments, annotation metadata, linked-file detection, storage-path discovery, and library statistics
- Health dashboard rows for Zotero, connection routes, SQLite, API, and normalized library contract
- Isolated unit, connector, SQLite, Web API, normalization, sample-library, and acceptance tests

## Read-only guarantees

The production connector contains no Zotero create, update, delete, tag edit, note edit, attachment edit, collection edit, upload, or `Library_ID` write operation. SQLite is opened with the native read-only flag and validates statements before execution. The Web API reader constructs GET requests only.

## Configuration

The connector selection and non-secret endpoint metadata live under `zotero` in `config/config.json`. API keys are accepted at runtime and should be sourced from the configured environment-variable name.

## Acceptance

Run:

```powershell
pwsh -NoProfile -File ./tools/Invoke-Tests.ps1
```

Every bootstrap and SPR-002 test must pass. Tests use a synthetic temporary SQLite fixture and mock Web API transport; they never modify a user Zotero library.
