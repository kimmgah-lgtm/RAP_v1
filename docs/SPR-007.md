## Turn A scope

SPR-007 adds project-specific quantitative coding without changing the canonical Common Study Review. A coding record is identified by `Library_ID + Project_ID`; one Library_ID may therefore hold different coding decisions in multiple projects.

The implemented project aggregate contains typed/extensible collections for Outcome, Comparison, Effect Size, Sample Size, Moderator, Study Arm, Measurement, Time Point, and Statistical Inputs. Outcome, comparison, time-point, arm, measurement, input, dependency-group, and effect IDs preserve one-to-many relationships and within-study dependency information. One project-paper record may therefore retain multiple outcomes, comparisons, time points, and effect sizes without assuming one paper equals one effect.

Every evidence value uses `SUPPORTED`, `INFERRED`, `NOT_REPORTED`, `UNCERTAIN`, or `CONFLICTING_EVIDENCE` and retains compact source, location, extraction method, confidence, generation, prompt, and schema provenance. Derived effect values retain transformation method, formula version, source-value references, and a derived/direct distinction; they do not replace reported inputs.

Researcher-confirmed fields are stored separately. AI output cannot populate or modify Effect Size Inclusion, Outcome Selection, Comparison Selection, Moderator Classification, Dependency Handling, Risk Judgment, Study Exclusion, Statistical Transformation Decision, researcher memos, or Common Review appraisal fields. Explicit researcher confirmation uses a separate command and a strict allowlist.

## Safety and execution modes

The engine exposes only `DryRun` and `Fixture` modes. There is no production connector or production write mode. DryRun performs no extraction or persistence. Fixture mode uses injected repositories and a deterministic mock extractor in tests. Payload hashes provide idempotent replay and conflict detection, and the state sequence `PLANNED -> EXTRACTED -> VALIDATED -> PATCH_PREPARED -> COMPLETED` permits recovery after an interrupted fixture write.

Local persistence extends the existing RAP SQLite queue rather than creating a separate ledger. `Operations` stores Meta Coding operation state; `ProjectRegistry`, `ProjectPaperMap`, `MetaCodingRecords`, and `MetaCodingAudit` store the fixture project boundary, coding aggregate, and audit events. The recovery test launches independent PowerShell processes: Process A persists `PATCH_PREPARED` and exits, then Process B reconstructs dependencies from SQLite and completes without re-extraction or duplicate effects.

Real AI providers, real Project Sheets, Notion, Zotero, and Google Drive writes remain disabled and untested. The official baseline identifies SPR-006 as complete, but its implementation and test artifacts are not present in this checked-out repository revision; the safe regression therefore executes every locally available test without changing that baseline declaration.
